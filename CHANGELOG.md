# shef.insync change log

## 2.0.0 — 2026-09-26

Модуль приведён к канону shef.options: сборка, тесты, CI, Composer,
документация в репозитории. Собран из рабочих копий 1.2.9 (база) и
1.2.10–1.2.12. Мажорная версия — из-за несовместимостей ниже.

**Несовместимо с 1.x**

* пакет Composer — `bxshef/insync`, тип `bitrix-module` с
  `installer-name = shef.insync`. Прежний `shef/insync` с типом
  `bitrix-d7-module` развернулся бы в `bitrix/modules/shef.shef.insync/` —
  каталог, которого ядро не знает;
* нужны PHP 8.2, `shef.options` 3.0.0 и `shef.problems` 2.0.0 и выше;
* от `shef.uiclear` модуль больше не зависит: цвета статусов — литералами,
  шаблоны компонентов — на штатных `ui.*` и загрузчике `main.loader`, пункт
  «Импорт» верхней панели (`Sync\Integration\Events`) удалён — страницы
  модуля в штатном левом меню `intranet`;
* компоненты ставятся в `/bitrix/components/shef.insync`, а не в
  `/local/components`. Копию 1.x установщик убирает: ядро смотрит в `/local`
  первым, и она перекрывала бы новую;
* `IProcess::getSyncEntityObject()` и трейт `TraitList\Sync\ClassSync`
  возвращают `IElement`, а не `EntityObject` (из 1.2.12);
* ajax-действия и страницы требуют прав — администратор либо «Запись» на
  модуль импорта (`Main\Access`). Раньше хватало входа на портал;
* `Agents\Entity` принимает в параметры только скаляры: строка агента
  исполняется ядром как код;
* удаление модуля стирает настройки и таблицу импорта; `savedata = Y`
  оставляет и то, и другое.

**Безопасность**

* любой вошедший на портал включал и выключал **любой агент портала** по ID
  (компонент статистики, контроллер страницы настроек), загружал файлы в
  импорт и чистил таблицу импорта — теперь права проверяются в самих
  действиях, агент сверяется с модулем в `b_agent`;
* SQL-инъекция в `SyncCollection::clear()` и `getStatisticByOriginator()`:
  код импорта из ajax-запроса шёл в запрос как есть;
* **каталоги импорта вынесены за корень сайта**: по умолчанию на уровень
  выше `DOCUMENT_ROOT`, для BitrixVM — `/home/bitrix/sh_import`; проект может
  задать свой в `/bitrix/.settings_extra.php` (`shef.insync` → `importDir`,
  только абсолютный путь). До 2.0.0 выгрузки лежали в `/upload/import`, и их
  отдавал веб-сервер. Внешние обмены перенастраиваются на новый каталог,
  старый модуль не трогает — перенос в `docs/security.md`;
* имя загружаемого файла шло в путь каталога импорта как есть: в
  `/upload/import/` ложились `.php` и `.htaccess`. Теперь — только имя без
  пути, без исполняемых расширений, с расширениями из `getImportFileAccept()`;
* «скачать пример» работал без входа и без csrf и подключал модуль и создавал
  объект класса, названные в запросе; теперь — вход, права, класс только из
  namespace модуля импорта;
* архивные файлы импорта назывались предсказуемо (код и дата до минуты) —
  добавлен случайный хвост;
* параметры агента вставлялись в строку агента без экранирования;
* ошибки импорта, имена агентов и ячейки грида выводились без экранирования;
* заголовки авторизации уходили в лог `AConnector` как есть — теперь маской.

**Исправлено**

* страница настроек падала с `shef.options` 3.x: `options_conf.php` передавал
  параметр `indexDoc`, которого больше нет;
* шаблон статистики звал `_showError()`, которой нет ни в одном модуле
  линейки, — fatal при выводе ошибок и подсказки;
* `clearRow` при ошибочном коде импорта продолжал работу и стирал строки
  всех импортов;
* `Manager::findAll()` резал строку агента по «([» и «,»: warning на агенте
  без параметров, запятая в значении рвала параметр. Теперь разбор
  токенайзером (`Manager::parseName()`), дата — в формате сайта, а не зашитом;
* настройка «сколько дней хранить файл» разбиралась `(int)`: «0» или мусор
  стирали архив импорта при каждом запуске;
* `ACsvProcess`: файл из одного заголовка давал «строку» из `false`, короткая
  строка и лишние колонки — warning;
* `ACrmProcess::getFactory()` и `ClassSync::getSyncClassSyncTableEntity()`
  держали результат в `static` внутри метода — второй импорт в том же хите
  получал фабрику и таблицу первого;
* `PropertyHelper::getPropertyByCode()` давал warning на первом вызове и
  перечитывал свойства инфоблока на каждом обращении к несуществующему;
* `AConnector` на ответ не 200 добавлял ошибку с пустым текстом;
* `AAgent`, `AFileProcess`, `ACrmProcess`, `CustomSectionProvider`: чтение
  ключей массива без проверки — warning на PHP 8;
* скрипт статистики падал на `reload()` без события (pull, после ajax);
* ссылки кнопок агента на странице настроек шли без `sessid` и отвергались
  csrf-фильтром ядра;
* namespace `Shef\Insync` и `Shef\InSync` приведены к одному написанию;
* аннотации ORM из `lib/**/meta/orm.php` (одна объявляла второй `CardTable`)
  сведены в `meta/orm.php` в корне модуля.

**Из рабочих копий 1.2.10–1.2.12**

* выбор источника библиотек XML (Composer проекта или своя копия) через
  `ShProjectContext` из shef.options; путь модуля — от корня сайта, а не
  зашитый `/bitrix/modules`;
* проверка версий модулей в установщике (`NEED_MODULES_BY_VERSION`);
* трейт `Sync\Model\IBlock\Element\PropertyTrait` — свойства инфоблока по коду;
* значения списка сравниваются без учёта регистра, ошибка создания значения
  называет свойство;
* `Section::setParentByXmlId()` не сбрасывает родителя, которого нет, и
  называет ненайденный XML_ID;
* `FromFile\AAgent` собирает результаты строк в `data->results`, метод
  `actionRabbitMq()` — обработка строк, переданных снаружи;
* сбой агента пишется с трассировкой.
