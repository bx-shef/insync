# Памятка агенту: shef.insync

Модуль Битрикс24 «коробки» и БУС — заготовки для синхронизаций: агенты с
учётом проблем, таблица импорта, импорт из CSV, XML и CRM, модели ORM,
обращение к внешнему API. Сам ничего не синхронизирует — на нём пишутся модули
обменов (пример — shef.demosync). Опирается на `shef.options` и
`shef.problems` и сделан по канону shef.options — сборка, тесты, раскладка,
решения, ловушки. Если здесь чего-то не хватает, смотрите
[CLAUDE.md shef.options](https://github.com/bx-shef/options/blob/main/CLAUDE.md):
всё, что там сказано про устройство модуля линейки, верно и здесь.

Проверка перед сдачей — всегда `./build.sh --check`, ровно это же гоняет CI.

**Как работа попадает в `main`** — [docs/agent-rules.md](docs/agent-rules.md):
только через PR; `/code-review` на каждый PR, а на изменения поведения,
безопасности, данных клиента, установщика и CI — панель из пяти проверяющих
(документация, инженер, QA, безопасность, CTO); чек-лист перед мержем и после;
рабочая дисциплина (замер вместо «должно», тест краснеет при поломке, никогда
`git checkout --`) и то, что необратимо и решается владельцем.

Тесты лежат в `tests/`, гоняются как обычные скрипты. Обвязка
`tests/assert.php` общая с shef.options: сравнение строгое, warning и notice —
провал. Ядро подменяется заглушками: общие — `tests/stub/bitrix.php`, свои
(CAgent, права на модуль, соединение с БД, ORM, контроллер, провайдер меню) —
`tests/stub/insync.php`, классы shef.options, от которых наследуются классы
модуля, — `tests/stub/options-lib.php`, трейты shef.options и shef.problems
под агентом, клиентом API и процессом импорта — `tests/stub/agent.php`, API
страницы настроек — `tests/stub/options.php`. Классы модуля и своя копия библиотек XML
подключаются **настоящие** автозагрузкой `tests/stub/autoload.php` — по тому же
соглашению, что на портале.

**Навыки — двух видов.** Навыки линейки (`shef-options-*`, `shef-new-agent`
и прочие из `MANIFEST`) — **копия**: их раскладывает `sync.sh --to` из
[bx-shef/options](https://github.com/bx-shef/options), там же их и правят.
Задача `Skills` в CI сверяет копию с источником и краснеет, когда источник
ушёл вперёд — это сигнал разложить заново, а не чинить копию.

Навыки про сам shef.insync — **локальные**, их источник здесь:
`shef-new-import` (импорт через таблицу и агент), `shef-new-api-client`
(клиент внешнего API на `AConnector`), `shef-use-insync-models` (модели и
драйверы каталога и инфоблоков). shef.options о получателях не знает, поэтому
они перечислены в `.claude/skills/LOCAL.MANIFEST`: после правки —
`.claude/skills/sync.sh --local`, иначе `--check` краснеет; `sync.sh --to`
их не трогает. Оформление — по правилам `.claude/skills/README.md` (evals
обязательны), классы `\Shef\InSync\...` из навыков проверяет
`tests/docs_test.php`, наличие — `tests/skills_test.php`.

Сигнатуры в навыках приведены дословно: поменяли абстрактный метод
`AFileProcess`, `FromFile\AAgent`, `AConnector` или драйвера — правьте и
навык.

**Примеры в `examples/` запускаются, а не читаются.** Как в shef.options:
`php examples/x.php` — на заглушках, `DOCUMENT_ROOT=/var/www/portal php
examples/x.php` — на живом портале. Шапка — ЦЕЛЬ, ГДЕ ПРИМЕНЯТЬ, ЧТО ДОЛЖНО
ПОЛУЧИТЬСЯ, ЗАПУСК. Полный импорт без портала не запустить (ORM, инфоблоки,
CRM), поэтому примеров два — строка агента и разбор XML.

## Опорные точки

**Импорт — в два шага через таблицу.** Процесс (`Sync\IProcess`: файл, CRM,
API) кладёт строки в `shef_insync_model` (`Sync\Model\SyncTable`); агент
разбора (`Sync\FromFile\AAgent`) берёт их пачками и разносит по сущностям,
стратегия (`Strategy\*`) решает, сколько брать и что делать с ошибочными.
Строки успешные удаляются, ошибочные остаются со статусом `F`. Ключ таблицы —
`ID`, внешний код (`ORIGIN_ID`) уникален в пределах кода импорта
(`ORIGINATOR_ID`); таблицу 1.x (ключ — один `ORIGIN_ID`) переводит
`SyncTable::init()`. Составным ключом не делать: `Strategy\MarkFail` меняет
код импорта у существующей строки, а часть первичного ключа ORM не меняет
(не сверено с ядром). Столкновение при этом переименовании — та же строка,
упавшая раньше: `MarkFail` её удаляет. Уникальность работает, только если
импорт сам задаёт внешний код (`setInterfaceOriginId()`), иначе он случайный.

**Библиотеки XML — из двух мест.** `.settings.php` решает при каждой загрузке
через `ShProjectContext` из `project-context.php` модуля `shef.options`, по
каждому namespace отдельно: есть каталог в vendor Composer проекта — своя
копия не регистрируется, нет — регистрируется `vendor/sbwerewolf/…`. Нет
`shef.options`, упал разбор `composer.json` проекта — своя копия. Путь модуля
считается от корня сайта; модуль вне корня — `/bitrix/modules/shef.insync`.
В 1.2.12 здесь стоял `Loader::includeModule('shef.options')` прямо в
`.settings.php` и зашитый `/bitrix/modules` — не возвращать.

**Свой namespace в `registerNamespace` не нужен:** ядро отображает
`Shef\InSync\Main\Utils` в `lib/main/utils.php` по соглашению, путь строчными.
Написание — `Shef\InSync` везде; в 1.2.9 половина файлов была `Shef\Insync`.
PHP это прощал, а `.settings.php` сверяет namespace контроллеров строкой.

**Права — одно правило, `Main\Access::canManage()`.** Администратор либо «W» и
выше на модуль импорта. Модуль — тот, чей агент (по `b_agent`, не из запроса)
или чей класс импорта (по его namespace). Проверяется в действии, не только на
показ кнопки. Агенты — только агенты импорта
(`Agents\Manager::getImportAgentModuleId()`, класс — наследник `AAgent`):
«W» на `sale` не открывает штатные агенты `sale`.

**Страницы — штатное левое меню `intranet`.** Раздел `shinsync` и страницы
ставит установщик из `installLeftMenu`, отдаёт
`Integration\Intranet\CustomSectionProvider`. Модули импорта добавляют свои
страницы загрузки в тот же раздел с `moduleId = shef.insync`. Верхней панели
(shef.uiclear) нет.

**Компоненты** — `install/components/shef.insync/` → `/bitrix/components`.
Класс компонента подключает `shef.options` до слова `class` и без него делает
`return`, а не `die()` (канон shef-new-component). Права — в `initParams()`:
он срабатывает и для страницы, и для ajax, и раньше, чем создаётся объект
импорта (его конструктор уже создаёт и чистит каталоги).

**Фронт** — `install/js/shef-insync/ui-anchors` → `/bitrix/js`, расширение
`shef-insync.ui-anchors` (страницы импорта в слайдере). Шаблоны — на штатных
`ui.*`, загрузчик — `BX.Loader` из `main.loader`, сетка — несколько правил
в `style.css` шаблона. `.min`-копий не держим.

**Установщик** — `install/index.php`, канонический из shef.problems
(`getModuleDir()`, `savedata`, проверка UTF-8 и версий) плюс таблица импорта
(`SyncTable::init()` / `drop()`) и `getLegacyDirList()` —
`/local/components/shef.insync` от 1.x, убирается и при установке, и при
удалении.

## Решения владельца

Это решения, а не баги. Не переигрывать без просьбы.

**База — рабочая копия 1.2.9.** Владелец прислал четыре архива; разбор и что
откуда взято — ниже, в «Рабочие копии».

**shef.uiclear не используем — штатные возможности Битрикс24.** Верхняя
панель — левым меню `intranet`, цвета статусов — литералами в `EStatus`,
bootstrap и карточки — `ui.*` и свои правила, загрузчик — `main.loader`.
Обработчик верхней панели (`Sync\Integration\Events`) удалён целиком, без
заглушки: в `installEvents` его не было ни в одной рабочей копии, то есть
регистрации на порталах нет.

**Composer — `bxshef/insync`, тип `bitrix-module`**, `installer-name =
shef.insync`, лицензия MIT, потолок `composer/installers`. Всё — ровно как в
shef.options и по тем же причинам (см. его CLAUDE.md, «bitrix-d7-module
развернул бы модуль не туда»). В 1.2.9 стояло `shef/insync` +
`bitrix-d7-module`. Линейка — своими пакетами `bxshef/options ^3.0` и
`bxshef/problems ^2.0`.

**Библиотеки XML: и Composer, и своя копия** — как Monolog в shef.problems.
Своя копия — xml-navigator **7.2.9** + language-specific **8.0.1** +
json-serialize-trait **1.0.2** (версии установлены сравнением с Packagist и
записаны в `vendor/versions.json`). Ветка 7.2 — потому что 8.x+ требуют PHP
8.4, а language-specific 8.4 переехал в другой namespace.

**Модуль поставляется только в UTF-8**, **настройки уходят вместе с модулем**
(`savedata = Y` оставляет) — как в shef.options. Таблица импорта — туда же:
уходит при удалении, остаётся с `savedata = Y`.

**Каталог импорта — вне корня сайта**, по умолчанию на уровень выше
`DOCUMENT_ROOT` (`/home/bitrix/sh_import` для BitrixVM), свой — в
`/bitrix/.settings_extra.php`, ключ `shef.insync` → `importDir`, только
абсолютный путь. Цена решения — внешние обмены, клавшие файлы в
`/upload/import/<код>/`, после обновления перенастраиваются; старый каталог
модуль не трогает (там данные), перенос — в `docs/security.md`. Модуль-импорт
по-прежнему может переопределить `getImportFolder()` и соседей.

**Обновление с 1.x — ручным `InstallFiles()`** без удаления модуля (удаление
стёрло бы таблицу импорта), см. `docs/portal-check.md`, шаг B. Автоматики не
делаем.

**Компоненты — в `/bitrix/components`**, как положено модулю из
`/bitrix/modules` (канон shef-new-component). Копию 1.x в
`/local/components/shef.insync` установщик удаляет: это пространство имён
самого модуля, а оставленная — перекрывала бы новую.

**Документация живёт в репозитории.** В поставке — только README, ссылки из
него на GitHub. Заметки по порталу конкретного заказчика, лежавшие в README
рабочей копии 1.2.9, в репозиторий не попали и попадать не должны: он публичный.

## Рабочие копии

Копии названы по версиям, а не по именам архивов: имена архивов — сокращения
заказчиков, а репозиторий публичный.

| копия | что это |
|---|---|
| 1.2.9 (2023-09-20) | чистый UTF-8, ядро модуля. **База** |
| 1.2.12 | в `version.php` 1.2.9, по CHANGELOG — 1.2.12+: то же ядро с правками 1.2.10–1.2.12; часть файлов в CP1251; рядом пустой `shef.sync` 1.0.3 |
| 1.2.12-bis | `version.php` 1.2.12: ядро копии 1.2.12 плюс клиентский код эпохи 1.0.x |
| 1.0.1 (2020) | старая версия: `aapi.php`, `aimport.php`, `@demo/` |

**Взято из копии 1.2.12:** выбор источника библиотек через
`ShProjectContext`, `NEED_MODULES_BY_VERSION` в установщике,
`PropertyTrait` (переписан без шестикратного копипаста и с исключением на
отсутствующее свойство), сравнение значений списка без учёта регистра и
текст ошибки, правка `Section::setParentByXmlId()`, `: void` у
`SectionTable::onUpdate()`, `IElement` вместо `EntityObject` в
`getSyncEntityObject()`, сбор результатов строк в агенте разбора (без
отладочных `echo`), трассировка в ошибке агента.

**Убрано решением владельца (2.0.0) — не возвращать без просьбы:**
`FromFile\AAgent::actionRabbitMq()` (из 1.2.12, вызывающих нет, модуля
очереди в линейке нет), демо-модель `Sync\Model\Hl\Demo`, интерфейсы
`IEntityProcess`, `IEntitySave`, `IPropertyCode` с трейтом, `TextTypeEnum`,
`Integration\Manager::getUrlShefInsyncModel()` — никем не использовались и
ехали на портал клиента. Формы «сохранить данные?» при удалении пока нет —
тоже решение.

**Не взято — не возвращать без просьбы:**

* из 1.2.12: `lib/main/options/agent.php` и `controller/agent.php` — вторая
  копия опции и контроллера агента с другим namespace (та же ловушка, что
  `oldoptions/` в shef.options); `install/local/admin/shef.insync/stat.import.local.php`
  — публичная страница на `header.php`, которую `installDir` не раскладывал;
  `meta/orm.php` в корне — старше аннотаций в `lib/` (поле `ADDITIONAL` ещё
  строкой); `docs/ru/` — старые версии тех же документов;
* из 1.2.12-bis — всё, чего нет в 1.2.12: `lib/onec`, `lib/oldonec` (форки обмена с
  1С ядра с правками под конкретных заказчиков), `lib/engine`
  (CRM, заказы, рассрочки, доставка, клиент-банк, факс — под конкретных
  заказчиков), `lib/site`, `lib/controllers`, `lib/entity`, `lib/fromfile`,
  `lib/install`, `aagent.php`, `aapi.php`, `aimport.php`, `auf.php`,
  `connect.php`, `secure.php`, `demo-api/`, `install/components/local`,
  `install/public`. Там же короткие теги `<?`, namespace `Shef\Sync` мимо
  каталога, адреса порталов заказчиков — репозиторий публичный;
* из 1.0.1 — ничего: её ядро полностью вошло в 1.2.x, а остальное — та же
  клиентская часть, что в 1.2.12-bis, и `@demo/` — копия старого
  `lib/`.

## Ловушки, за которые заплачено

**Права «вход на портал» — не права.** `Actions\Normal` — умолчания ядра:
аутентификация и csrf. В 1.2.9 им закрывалось всё — и включение/выключение
агента по ID, и загрузка файла, и очистка таблицы. Агентом по ID можно было
выключить любой агент портала, включая агенты ядра. Права проверять в
действии, агент — сверять с `b_agent`.

**SQL руками — только через `forSql()`.** `SyncCollection` собирает запросы
сам, и код импорта в `clear()` приходит из ajax. Было — конкатенация.

**Строка агента — это PHP-код.** Ядро исполняет её `eval`. Параметры —
`var_export()`, только скаляры; для обычных значений строка совпадает с 1.x,
иначе агенты на портале перестали бы находиться по имени.

**Имя файла от браузера — не имя файла.** В 1.x каталоги импорта были под
`/upload`, и без проверки в них ложились `.php` и `.htaccess`. Проверка — в
`prepareUploadName()`, и расширения из `getImportFileAccept()`.

**Выгрузка под корнем сайта — открытый файл.** В 1.x каталоги импорта были
`/upload/import`, а архив назывался `done_<код>_<дата до минуты>` — перебор
за срок хранения. Теперь каталог вне корня сайта (`Constants::getImportDir()`,
как логи shef.problems), а случайный хвост в имени — вторая линия.

**Ошибка, после которой код идёт дальше, хуже исключения.** `clearRowAction`
добавлял ошибку «нет кода импорта» и всё равно звал `clear('')` — стирание
строк всех импортов.

**`static` внутри метода — одна переменная на класс и наследников** (PHP 8.1+).
`ACrmProcess::getFactory()` отдавал второму импорту CRM фабрику первого.
Кешировать — в свойство объекта.

**Пустая строка из агента — удаление агента.** Ядро снимает из `b_agent`
агент, вернувший `''`. `AAgent::process()` возвращал её и тогда, когда не
подключились модули: агент пропадал насовсем после одного неудачного хита.
`''` — только по `isNeedStop()`.

**Пустой `catch` в установщике — «установлено» без таблицы.** Таблица
импорта создаётся первой и без глушения: не создалась — установка
прерывается с причиной.

**Функция из чужого окружения.** Шаблон статистики звал `_showError()` —
её нет ни в одном модуле линейки, была, видимо, в `def-functions.php`
проекта. На чистом портале — fatal.

**`.min` побеждает исходник.** Ядро берёт `script.min.js`, если он есть:
исправили `script.js` — на портал уехал бы старый min. Min-копий не держим,
`assets_test.php` это сторожит.

**Аннотации ORM — не в `lib/`.** `meta/orm.php` объявляет `EO_*` «для вида», а
в `lib/` их ищет автозагрузка; одна из трёх объявляла второй `CardTable`.
Теперь один файл в корне, никем не подключается.

**Замена файлов не запускает установщик.** Компоненты 1.x в `/local` на
обновлённом портале остаются и перекрывают новые. Порядок обновления — в
`docs/portal-check.md`, шаг B: `InstallFiles()` без удаления модуля (удаление
стёрло бы таблицу импорта).

**Проверяй артефакт, а не свой диф** — как в shef.options. И репозиторий
публичный: рабочие копии владельца несут адреса порталов заказчиков, SQL по их
данным, ID пользователей. Грепать всё, что переносится.

## Известные шероховатости

Не трогать заодно — отдельной задачей, с проверкой на портале.

* **Своя копия xml-navigator 7.2 даёт deprecation на PHP 8.4** в
  `XmlConverter`, `FastXmlToArray`, `XmlElement`. Модуль их не загружает
  (`vendor_test.php` проверяет, что загружает), но модуль-импорт, который
  позовёт их сам, получит deprecation в лог. Ветки без них требуют PHP 8.4.
* `Agents\AAgent` — синглтон: параметры и состояние живут между вызовами
  `process()` в одном хите (так устроено с 1.x).
* `AFileProcess::__construct()` создаёт каталоги и чистит архив при каждом
  создании объекта, в том числе на показ страницы загрузки.
* Права сравниваются буквой: `>= 'W'`. Модуль с нестандартными буквами прав
  (не D/R/W/X) может дать неожиданный ответ.
* `Options\Import\FromFile\Option::addEventHandler()` вставляет JS-код
  обработчика в страницу как есть — это код разработчика модуля, не данные,
  но и не экранируется.
* Тестами не покрыты `ACsvProcess::import()`, `AXmlProcess::import()`,
  модели инфоблоков, каталога и драйверы — нужны `CCSVData`, ORM, `iblock`,
  `catalog`. Проверка — на портале.
* `tests/stub/options.php`, `options-lib.php` и `agent.php` повторяют API
  shef.options 3.x и shef.problems 2.x. Поменяется API — заглушки менять
  вместе с ним.
* `AConnector` выставляет заголовки на общий `HttpClient`: заголовок одного
  запроса остаётся на следующих запросах того же объекта. Уходит ли
  `Authorization` при переадресации (`redirect = true`) на чужой хост — не
  проверено, это поведение `HttpClient` ядра. Проверка — на стенде.
* Сигнатуры `HttpClient::waitResponse()`, `setTimeout()` ядра не сверены:
  `AConnector` приводит типы сам, тест — на заглушке.
* Очистка таблицы со страницы статистики требует прав на `shef.insync`, а не
  на модуль импорта, чьи строки стираются. Так решено для страницы
  статистики (`docs/security.md`); менять — решением владельца.
* Размер загружаемого файла ограничен только настройками PHP;
  `ACsvProcess` читает файл целиком.
* DDL таблицы импорта — MySQL (как и в 1.x); уникальный индекс на два
  `VARCHAR(255)` требует формата строк `DYNAMIC` (умолчание с MySQL 5.7).
  Проверка — на стенде, шаг B.
* Пустой `DOCUMENT_ROOT` — каталог импорта во временном каталоге системы,
  как логи в shef.problems. На портале ядро задаёт корень всегда, в том числе
  для агентов на cron.

## Приёмочный чек-лист

Процедура — [docs/portal-check.md](docs/portal-check.md): шаги с ожидаемым
результатом и бланк. Проходить **перед сдачей** и **на отдельном стенде**.

Главный сценарий для 2.0.0 — обновление со стенда с 1.2.x: страница настроек
открывается с `shef.options` 3.x, компоненты 1.x из `/local` ушли, таблица
импорта цела и переведена на ключ `ID` (`SyncTable::init()`, агенты на это
время выключены), страница статистики работает, пользователь без прав не может
тронуть агент, `.php` в импорт не загружается.
